# 元実装との差分

参照元: <https://github.com/2509-hackz-ichthyo/main>

## 維持する体験

- 8×8盤面と中央4駒の初期配置
- 0〜255のグレースケール駒
- 挟んだ駒を`(a1+a2+b1)/3`で中間色へ変える
- 最終盤面の平均色で黒寄り・白寄りの勝者を決める
- 二人対戦と対局再生へ拡張できる状態モデル

## 意図的に変える点

### 固定端色を最遠駒に統一

元実装のコメントは最遠の挟み駒を`a2`と説明するが、コードの一部は変換対象末尾を参照する。v1契約ではコメントどおり最遠の固定端を使い、全色を着手前盤面から同時計算する。

### 乱数をseed付きLCGへ変更

元実装は実行時刻seedのGo乱数を使う。v1は再現可能な棋譜と複数runtime間の一致を優先し、32bit LCGを契約化する。

### 行き詰まり終了を追加

元実装は盤面が満杯の場合だけ終了し、合法手がない場合の終了はTODOになっている。v1は合法手がない場合のパスと、二者連続パスでの終了を定義する。

### サーバーを盤面の正本にする

元実装にはクライアント側とLambda側へゲーム判断が分散している箇所がある。v1はルールruntimeの結果だけを確定状態とし、UIは成功response/eventを描画する。

### Whitespace棋譜との互換性を持たせない

元実装のWhitespace変換APIとAWS依存の保存形式は移植しない。後続Issueでは「実行可能ななでしこコードそのものを棋譜にする」方式を採用する。
