# グラデーションリバーシ・ゲーム規則 v1

## 盤面とプレイヤー

- 盤面は8行×8列。座標は0始まりの`row`、`col`で表す。
- JSON上の盤面は64要素のrow-major配列で、indexは`row*8+col`。
- 空きマスは`null`、駒は0（黒）〜255（白）の整数で表す。
- プレイヤーは先手`dark`、後手`light`。駒色はプレイヤー所属を表さず、どちらも0〜255の駒を置く。
- 初期配置は`(3,3)=0`、`(4,4)=0`、`(3,4)=255`、`(4,3)=255`。

## 次の駒色

ゲーム作成時に0〜4294967295のseedを受け取る。次の式を32bit符号なし整数として1回評価し、更新後stateの上位8bitを`nextColor`とする。

```text
state = (state * 1664525 + 1013904223) mod 4294967296
nextColor = floor(state / 16777216)
```

新規ゲーム時と、受理された着手・パスの後だけstateを進める。不正commandでは進めない。seedが1なら最初のstateは1015568748、`nextColor`は60になる。

## 合法手

着手候補が空きマスであることを確認し、そこから縦・横・斜めの8方向を独立に走査する。

1. 隣接マスから同じ方向へ、空きマスまたは盤外まで連続する駒を集める。
2. 連続駒が2個以上なら、その方向は挟み成立。
3. 最遠の1個を固定端とし、それより手前の駒を変換対象にする。
4. 1方向以上で挟みが成立するマスだけが合法手。

通常のリバーシと異なり、駒色から敵味方を判定しない。初期盤面では12マス、`(2,2)`、`(2,3)`、`(2,4)`、`(2,5)`、`(3,2)`、`(3,5)`、`(4,2)`、`(4,5)`、`(5,2)`、`(5,3)`、`(5,4)`、`(5,5)`が合法手になる。

## 色変換

成立方向ごとに、次の値を着手前盤面から取得する。

- `a1`: 新しく置く`nextColor`
- `a2`: 最遠にある固定端の色
- `b1`: 変換対象駒の色

各変換対象の新しい色は`floor((a1+a2+b1)/3)`。複数の駒や方向はすべて着手前の値から同時に計算し、走査順に依存させない。

例: seed=1の最初の駒色60を`(2,2)`へ置くと、`(3,3)`が変換対象、`(4,4)`が固定端になり、`floor((60+0+0)/3)=20`へ変化する。

## 手番、パス、終了

- `currentPlayer`のcommandだけを受理する。
- 受理したcommandごとに`turnNumber`を1増やし、手番を交代する。
- 合法手が0件のときだけ`pass`を受理する。
- 盤面が満杯、または二人が連続で有効なパスを行ったとき終了する。

終了時、全駒の色合計を`sum`、駒数を`count`とする。浮動小数を使わず、`2*sum < count*255`なら`dark`、それ以外なら`light`の勝利とする。平均127.5ちょうどは元実装互換で`light`が勝つ。

## 不正command

範囲外、占有済み、挟み不成立、手番違い、古いturn、許可されないパス、終了後のcommandは拒否する。拒否時は盤面だけでなく、turn、手番、乱数、連続パス数を含む状態全体を変更しない。
