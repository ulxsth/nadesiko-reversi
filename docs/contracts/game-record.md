# 対局記録 v1

対局記録は二つの表現を持つ。

| 表現 | 実体 | 役割 |
| --- | --- | --- |
| 実行可能ななでしこ棋譜 | `<gameId>.nako3` | 保存形式。ファイルそのものが再生プログラム |
| JSON対局記録 | `game-record.schema.json` | APIとプロセス内で受け渡す構造化表現 |

保存形式は前者を正本とする。棋譜の読み取りは「パースする」のではなく「gonakoで実行する」ことで行い、実行結果としてJSON対局記録が得られる。ルールが決定的な純関数であるため、`seed`と受理済みcommand列だけで全stateを復元できる。

## 実行モデル

棋譜1本の検査・読み取り・再生は、**gonakoの1プロセスで完結する**。再生ハーネスがルール本体を取り込み、全手の適用と各手の盤面生成までを同じプロセスの中で行う。

```text
server/internal/replay
  └─ gonako（1回だけ起動）
       ├─ rules/replay/harness.nako3   … 許可語彙の定義と再生
       │    └─ !「rules/game/rules.nako3」を取り込む
       └─ <棋譜>.nako3                  … 指し手の列
```

起動回数は手数に比例しない。常駐プロセス、プロセスプール、daemonは使わない。one-shotの子プロセスなので、ECS/Fargateにもそのまま置ける。

`rules/game/rules.nako3`は関数定義と定数だけを持ち、取り込んでも何も実行しない。標準入力JSONのCLIは`rules/game/main.nako3`が持ち、ルール本体を同じように取り込む。CLIと再生で同じルールを使うため、両者の結果は必ず一致する。

### ファイルの扱い

| 対象 | 扱い |
| --- | --- |
| ルール本体・ハーネス | 読み取りのみ。読み取り専用配置で動作する |
| 連結した実行用ソース | OSの一時領域（AWSでは`/tmp`）に呼び出しごとの固有名で作り、実行後に必ず削除する |

一時領域以外へは書き込まない。実行が失敗した場合も削除する。

## 保存場所

```text
records/<gameId>.nako3
```

`gameId`はファイル名に使うため、`[A-Za-z0-9_-]{1,64}`に制限する。

## 文法

```ebnf
記録     = { ヘッダ行 | 空行 } , 版宣言行 , { 空行 } , 開始行 , { 手行 | 空行 | 注釈行 } , [ 終了行 ] , { 空行 } ;
ヘッダ行 = "#" , 任意文字列 ;
注釈行   = "#" , 任意文字列 ;
版宣言行 = "「" , ルール版 , "」でルール版宣言" , [ 注釈 ] ;
開始行   = "「" , ゲームID , "」と" , 種 , "で対局開始" , [ 注釈 ] ;
手行     = 着手行 | パス行 ;
着手行   = 行 , "と" , 列 , "で" , 手番語 , "着手" , [ 注釈 ] ;
パス行   = 手番語 , "パス" , [ 注釈 ] ;
終了行   = "「" , 手番語 , "」で対局終了" , [ 注釈 ] ;
注釈     = { " " } , "#" , 任意文字列 ;
手番語   = "黒" | "白" ;
行       = "0" | … | "7" ;
列       = "0" | … | "7" ;
種       = 0〜4294967295 の十進整数 ;
ルール版 = 文字列 ;
```

1行1手。**手行の並び順が0始まりの`turnNumber`そのもの**であるため、`expectedTurn`は記録しない。行位置が手を一意に識別するため、`commandId`も記録しない。

手番語は契約の`player`と1対1で対応する。

| 棋譜 | 契約 |
| --- | --- |
| `黒` | `dark` |
| `白` | `light` |

助詞を`で`に揃えたのは、`rules/game/rules.nako3`の既存定義（`行と列で盤内判定`など）に合わせるため。

## 許可語彙

棋譜が使ってよい語はこれだけ。

| 語 | 例 | 回数 |
| --- | --- | --- |
| `ルール版宣言` | `「1」でルール版宣言` | ちょうど1回 |
| `対局開始` | `「demo-1」と1で対局開始` | ちょうど1回 |
| `黒着手` | `2と5で黒着手` | 0回以上 |
| `白着手` | `5と4で白着手` | 0回以上 |
| `黒パス` | `黒パス` | 0回以上 |
| `白パス` | `白パス` | 0回以上 |
| `対局終了` | `「白」で対局終了` | 0回または1回 |

**これ以外の行はgonakoを起動する前に拒否する。** 棋譜は実行して読むため、許可語彙を素通しにすると任意コード実行経路になる。読み取り側は許可リストとして働き、上の7語と`#`で始まる注釈行・空行以外はすべて`record_syntax_error`にする。変数代入、関数定義、`取り込む`、表示、ファイル操作、OS実行はいずれも通らない。

## 例

```nako3
# グラデーションリバーシ 対局記録 v1
# 開始 2026-09-12T21:30:00+09:00
# 終了 2026-09-12T21:44:12+09:00

「1」でルール版宣言
「demo-1」と1で対局開始

2と5で黒着手    # 色60、1個変換
5と4で白着手    # 色94、1個変換
6と4で黒着手    # 色129、2個変換
# …（中略）…

「白」で対局終了   # 61手、色合計8891、駒64
```

完全な60手の実例は`rules/replay/sample-game.nako3`にある。

## ルール版と互換性

版宣言行は必須とする。棋譜が前提とするルール版を棋譜自身が持つことで、ルールの振る舞いが変わった後でも古い棋譜を黙って誤再生せず、明示的に拒否できる。

- 現在のルール版は`1`
- 再生側は自分が再生できる版だけを受理し、それ以外は`record_unsupported_rules_version`で拒否する
- 判定はgonakoを起動する**前**に行う。未対応の棋譜へルールを当てても意味がないため
- 拒否するときは版宣言行の行番号とその行のソースを添える
- ルールの振る舞いを変えたら版を上げる。盤面、合法手、色変換、乱数、終了条件、勝敗のいずれかが変われば対象

JSON対局記録の`rulesVersion`も同じ値を持ち、棋譜とJSONのどちらから読んでも版が分かる。

## 注釈の扱い

注釈（`#`以降）は再生時に無視される。書かれる値はすべて盤面と`rngState`から決定的に導かれるため、注釈は人間可読性と同時に**自己検証**として働く。

| 位置 | 内容 |
| --- | --- |
| 着手行 | 置いた駒の色（`nextColor`）と、その手で変換された駒数 |
| 終了行 | 総手数、終了盤面の色合計、駒数 |
| ヘッダ | `開始`と`終了`の時刻。RFC 3339 |

厳密照合モードでは、再生結果と注釈の導出値を突き合わせる。不一致は棋譜の破損またはルール変更を意味し、`record_mismatch`になる。

## 書き込み規則

- 受理されたcommandごとに1行appendし、行単位でflushする
- **拒否されたcommandは書かない。** 拒否時は`rngState`を消費しないため、書くと再生がずれる（`gradient-reversi-rules`の「拒否時の原子性」を参照）
- 版宣言行と開始行は`newGame`の直後に1回だけ書く。版宣言行が先
- 終了行は`phase`が`finished`になった時点で1回だけ書く。終了行のない記録は進行中とみなす

サーバー再起動時の復旧、途中参加者への追いつき、棋譜再生はすべてこのファイルの再実行で行う。stateを別途永続化しない。

## 再生

`rules/replay/harness.nako3`が許可語彙を定義し、`rules/game/rules.nako3`の`新規ゲーム作成`・`着手適用`・`パス適用`へ委譲する。ハーネスは初期局面を先頭に、各手の適用後stateを順に返す。手数`n`の棋譜からは`n+1`個の盤面が得られる。

指定手数だけを取り出す場合も、再生そのものは常に最後まで1プロセスで走る。切り詰めるのは返す盤面だけで、棋譜全体の合法性は常に検証される。

再生の成功条件は`runtime-protocol`の「対局記録」要件と同じ。記録のcommand列を`seed`から順に再適用した結果が、保存された最終stateと一致すること。棋譜が実行可能であること自体がこの要件の検証になる。

## エラー

再生失敗は行番号とその行のソースを添えて返す。

| code | 条件 |
| --- | --- |
| `record_syntax_error` | 許可語彙の外、または文法に合わない行がある |
| `record_missing_header` | 版宣言行または開始行が無い、あるいは2回以上ある |
| `record_illegal_move` | 再生中にcommandがルールへ拒否された |
| `record_mismatch` | 厳密照合モードで注釈の導出値が再生結果と一致しない |
| `record_unfinished` | 完了記録として読んだが終了行が無い |
| `record_unsupported_rules_version` | 版宣言行のルール版に対応していない |

`record_illegal_move`にはルール側のerror code（`occupied`、`illegal_move`、`pass_not_allowed`など）も添える。

## JSON対局記録との対応

| 棋譜 | `game-record.schema.json` |
| --- | --- |
| 版宣言行のルール版 | `rulesVersion` |
| 開始行のゲームID | `gameId` |
| 開始行の種 | `seed` |
| ヘッダの開始時刻 | `startedAt` |
| ヘッダの終了時刻 | `endedAt` |
| 手行の並び | `commands[]`（`expectedTurn`は0始まりの行順、`commandId`は再生時に採番） |
| 終了行の手番語 | `winner` |
| 再生後の最終盤面 | `finalState` |
