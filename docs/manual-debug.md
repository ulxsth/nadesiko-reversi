# 統合デモの手動デバッグ

実server、gonako、ブラウザをまたぐ挙動は、自動E2Eではなくこの手順で確認します。ルールや状態遷移のpackage testは、引き続き`make check`で実行します。

## 実施情報

統合PRへ次を記録してください。

- 対象commit:

- 実施者:
- OS / ブラウザ:
- 結果: PASS / FAIL
- 補足または失敗時の再現手順:

## 準備

初見のPCではWSL2 Ubuntu 24.04でリポジトリを取得し、次を順に実行します。`README.md`の案内で迷った箇所は記録し、READMEの修正が必要なら人間タスクとして起票します。

```bash
make bootstrap
make check
make dev
```

`curl http://127.0.0.1:4173/healthz`で`goReady`と`gonakoReady`がともに`true`、`http://127.0.0.1:4173/`で画面が返ることを確認します。別プロセスが4173番を使用中なら、そのプロセスを終了してから再実行します。

二人対戦は同じ端末の別ブラウザ、または通常窓とプライベート窓で`http://127.0.0.1:4173`を開いて試します。同一タブを複製すると参加者IDが共有される場合があるので避けてください。サーバーは同一originのWebSocketだけを許可します。

画面で合法手以外を選ぶ場合、クライアントが先に拒否する場合があります。サーバーからの拒否・`stale_turn`を個別に調べる場合は開発者ツールから該当WebSocketへ`commandId`、`type`、`player`、`expectedTurn`を含むJSON commandを送ってください。通常の手動確認では画面の表示を主に確認します。

統合PRには実施情報と上表の結果を記載してください。GitHub Actionsが遅延していても、ローカル`make check`の結果と手動結果は別々に記録します。

## 基本スモーク

- [ ] 画面を開くとseed 1の新規対局が開始し、8×8盤面、手番、次の駒色、合法手が表示される
- [ ] 合法手を1か所選ぶと盤面と手数が更新され、手番がdarkからlightへ交代する
- [ ] 既に駒があるマスを選んでも盤面と手数は変わらず、日本語の拒否メッセージが表示される
- [ ] seedを42にして「新しい対局」を押すと手数0へ戻る
- [ ] seed 42で1手進めた後、再びseed 42で新規対局にすると、最初の盤面、次の駒色、合法手が同じになる

## パスと終局

- [ ] 合法手を順に選んで進め、合法手がない手番ではパスだけが実行可能になる
- [ ] パス後も同じ確定盤面を保ったまま、手数・手番・連続パス数が更新される
- [ ] 盤面が埋まるか連続2回パスになると対局が終了し、以後は着手できない
- [ ] 終了表示に勝者と盤面の全駒の平均色が表示される

## 失敗時

ブラウザの開発者ツールでローカルAPIのrequest/response、またはWebSocketの送受信JSONを保存し、server標準エラー出力と合わせてPRへ添付します。盤面の不一致は、gameId、直前のturn number、担当席、操作したrow/colを必ず記録します。
