## Context

現在のブラウザUIは`web/main.nako3`の`既定表示更新処理`で`phase=finished`を判定し、右側の状態文言を更新する。`web/index.html`には終局専用要素がなく、再描画のたびに新しいDOMを生成する仕組みもない。詳しい目的はproposal.md、表示契約は`specs/browser-game-ui/spec.md`を参照する。

## Goals / Non-Goals

**Goals:**

- 既存の確定state適用経路から終局表示を更新する
- DOMを一度だけ定義し、表示・非表示と文言だけを切り替える
- 既存の白黒・DotGothic16・角丸なしのデザインへ合わせる
- Issue #34の専有パスだけで変更を完結する

**Non-Goals:**

- 勝敗計算や通信responseの変更
- フォーカストラップ、閉じるボタン、アニメーション
- #35が扱う右側パネルの情報整理

## Decisions

### 静的なlive regionをHTMLへ置く

`web/index.html`へ初期状態が`hidden`の終局要素を1個だけ定義し、`aria-live="assertive"`と`aria-atomic="true"`を付ける。なでしこ側はこの要素の文言と`hidden`属性だけを更新する。動的生成より重複を構造的に防げ、`alert()`より表示と支援技術の挙動を制御しやすい。

### 表示判定を既定表示更新処理へ集約する

`phase`と`winner`の解釈は`既定表示更新処理`から専用の表示・非表示処理へ渡す。`dark`と`light`の表示変換も専用処理内に閉じ、既存の「先手 dark」「後手 light」という手番表示用関数を流用しない。不正なwinnerではポップアップを隠し、既存状態欄をエラーへ変える。

### 新規対局操作時に先に隠す

終局stateから新規対局requestを送る時点でポップアップを隠す。response到着後だけ隠す案では、通信中にも古い勝者が表示され続けるため採用しない。request失敗時は既存の通信エラー表示が状況を伝える。

### ページ中央へ固定配置する

`web/styles.css`でviewport中央へ固定し、白地・黒枠・角丸なしで既存デザインに合わせる。背景全体を操作不能にせず、「新しい対局」操作を維持するため、ポップアップは通知表示として扱う。

### 専有パスと統合点

変更は`web/index.html`、`web/main.nako3`、`web/styles.css`、`openspec/changes/show-result-popup/**`に限定する。サーバーから届く`phase`と`winner`を既存のまま利用し、#5・#30のパスには触れない。#35は本変更のマージ後に同じWebファイルを更新する。

## Risks / Trade-offs

- [ポップアップが盤面の一部を隠す] → 文言だけの小さな通知にし、盤面操作が不要な終局時だけ表示する
- [無効stateで誤った勝者を示す] → `dark`と`light`以外では表示せず、状態欄をエラーにする
- [再描画で読み上げが繰り返される] → 同一要素を再利用し、同じ終局stateでは文言を変更しない
- [新規対局requestが失敗して結果が消える] → 古い結果より現在の通信エラーを優先し、確定state自体は保持する

## Migration Plan

1. 静的な終局要素を非表示状態で追加する
2. なでしこ側へ表示・非表示処理を追加し、既存のstate更新へ接続する
3. CSSで中央表示と`hidden`時の非表示を定義する
4. finished fixtureと新規対局操作で表示ライフサイクルを確認する

問題があれば3ファイルの変更をまとめてrevertし、従来の右側状態表示だけへ戻せる。
