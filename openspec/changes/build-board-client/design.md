## Context

`openspec/specs/runtime-protocol/spec.md`がstateとcommandの正本である。ブラウザ版なでしこ3（`web/vendor/wnako3.js`、3.8.1）はCanvas描画、DOM操作、キー・マウス・タッチイベント、`AJAX_JSON取得`を持つ。

Issue #4の専有パスは`web/**`（vendorを除く）だけなので、サーバーへの登録も`server/main.go`の変更も行わない。#7が配線できるよう、送信の出口を1関数に閉じる。

## Goals / Non-Goals

**Goals:**

- stateを唯一の描画入力にし、盤面の正本をサーバー側に置いたままにする。
- playerの操作を契約のcommandへ変換し、送信前に内容を確認できるようにする。
- 通信なしで主要な表示状態を再現できるようにする。
- 狭い画面とキーボードだけでも操作できるようにする。

**Non-Goals:**

- transportの実装、対局の保持、棋譜再生。
- ルール判断の複製。

## Decisions

### 送信の出口を1関数に閉じる

`ルール要求送信`だけがサーバーへの出口で、他の関数はcommandを組み立ててこれを呼ぶ。`接続方式`が`fixture`のときは送信せず、送信予定のcommandを画面へ出して待機する。#7は`接続方式`が`server`の分岐に実送信を足すだけでよく、UI側の構造を変えずに済む。

### 確定応答までUIの盤面を書き換えない

着手しても更新するのは選択枠と送信予定commandだけで、`現在状態`には触れない。盤面が変わるのは`状態適用処理`がサーバー由来のstateを受け取ったときだけにする。楽観更新を入れないので、拒否されたcommandで盤面が巻き戻る挙動が起きない。

### 合法手はlegalMovesだけを見る

挟み判定も色変換もブラウザでは計算せず、stateの`legalMoves`に含まれるかどうかだけを判定する。UIが独自にルールを持たないため、ルール変更がサーバー側だけで完結する。手番違いや終了後の操作も、stateの`currentPlayer`と`phase`を読むだけで判断する。

### 事前チェックのメッセージを契約のerror codeへ対応させる

手番違い、非合法手、終了後の操作、合法手があるときのパスは、送信前に日本語で伝える。これは契約の`not_your_turn`、`illegal_move`、`game_finished`、`pass_not_allowed`と同じ条件で、#7が実応答を受けたときも同じ文面を使える。

### fixtureは実ルールengineの出力から作る

`web/fixtures/*.json`は手書きせず、gonakoのルールengineで実際に対局を進めて得たstateを保存する。`pass-required.json`だけは自然な対局で現れなかったため盤面を構成し、engineが`pass`を受理することで合法手0件を確認した。契約と実装の両方に忠実なfixtureになる。

### Canvasは内部解像度を固定し、入力座標を換算する

Canvasは640×640固定で描き、表示サイズはCSSで縮める。なでしこの`マウスX`はCSSピクセル基準なので、`clientWidth`から倍率を求めて盤座標へ直す。描画コードを画面幅から独立させられる。

### 画面を白黒にし、区別は形で行う

配色は白と黒だけにし、色を持たせるのは背景の`#e3dcd8`だけにする。角丸は使わない。書体はDotGothic16で、読み込めない環境では等幅へ落ちる。

駒は0〜255のグレースケールそのものが情報なので、盤と装飾から彩度を抜くと駒の階調が最も強い手がかりになる。一方で色による区別が使えなくなるため、次の3つは形で分ける。

| 要素 | 形 |
| --- | --- |
| 合法手 | マス中央の小さな四角 |
| キーボードカーソル | マス内側の細い枠 |
| 選択中（送信予定） | マス四隅の印 |

駒の輪郭は常に墨色にする。白い駒（255）が白い盤に沈むのを防ぐためで、暗い駒と明るい駒で輪郭を出し分けるより単純になる。エラー表示は色ではなく白黒反転で示す。

### 画面から文字を減らす

キャッチコピー、操作説明、開発用リンク、注記は画面に置かない。キーボード操作の説明はCanvasの`aria-label`へ移し、支援技術には残す。座標ラベル（a〜h、1〜8）も置かず、盤面をマスと駒だけにする。状態表示は契約のerror codeと対応する短い日本語に留める。

### キーボードはカーソルと確定を分ける

矢印キーでカーソルだけを動かし、Enterまたはスペースで着手する。Pでパスする。Canvasに`tabindex`を与え、フォーカスリングをCSSで出す。

### ファイルを分割せずmain.nako3へ収める

`web/components/**`への分割は行わない。wnako3の取り込み機構はブラウザでのパス解決が絡み、P0の規模では分割の利点より不確実性が上回る。関数単位で節を分け、分割が必要になった時点で切り出す。

## Risks / Trade-offs

- [なでしこ3の変数名が組み込み命令と衝突するとコンパイルが通らない] → 変数名を命令一覧と突き合わせて検出する手順を取り、`範囲内`と`一致`を改名した。
- [`条件<式の要素数`のような比較を直接書くとパースが意図とずれる] → 要素数を変数へ入れてから比較し、反復は`回`ループに統一した。
- [ブラウザ実機でしか確認できない部分がある] → jsdom上でwnako3を動かし、コンパイル・初期描画・クリック・キーボード・パス・fixture切替・拒否表示に加え、canvasへ彩度のある色が渡っていないことを自動で確認した。実際の見え方、DotGothic16の表示、実画面でのレスポンシブ、タッチ操作は実機確認に残る。
- [書体をGoogle Fontsから読むため外部依存が増える] → `.tools/`へ固定する他のツールと違い取得先を固定できないので、等幅へのフォールバックを指定し、読み込めなくても操作に影響しないようにした。
- [fixture表示では着手しても盤面が進まないため、操作感の確認が限定される] → 送信予定commandを画面に出して、何が送られるかを読めるようにした。実際の進行確認は#7の統合後になる。
